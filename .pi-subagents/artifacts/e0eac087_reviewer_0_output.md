## Review

### Verdict
**Request changes / not spec-compliant.** The canonical resource/session wiring is largely correct, but the implicit `nebula-pulse` theme override is discarded by the SDK reload that immediately follows it. This is a blocker for Task 4's explicit non-persistent theme requirement.

### Correct / strengths
- `src/extension.ts:181-184` resolves `getCanonicalAgentDir()`, sets `PI_CODING_AGENT_DIR`, and creates it before the first dynamic SDK import/use in activation. The CodePi session directory remains separately derived from `context.globalStorageUri` at `src/extension.ts:190-191`.
- `src/extension.ts:1248-1267` builds the `rpiv-todo` path from the passed canonical `agentDir`, not from an independently hard-coded home path, and degrades cleanly when it is absent.
- `src/pi-runtime-config.ts:29-57` is a pure, testable path policy. Explicit `false` values are honored by `getEnabledBundledResources`, and the tests cover default paths, disabling resources, and the agent-relative todo path.
- `src/extension.ts:1276-1283` supplies the canonical `cwd`/`agentDir`, shared `settingsManager`, bundled additional paths, and `noExtensions: false`. This matches the SDK's `DefaultResourceLoader` contract; SDK inspection confirms `noExtensions` defaults false and normal package resources are included when it is false (`node_modules/@earendil-works/pi-coding-agent/dist/core/resource-loader.js:268-271`).
- `src/extension.ts:1284-1297` uses the SDK-supported `extensionsOverride` hook and places identified additional/bundled extension objects after the base list. The SDK's extension runner resolves tools using first registration (`node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/runner.js:251-262`), so this ordering gives normal user/project entries precedence over bundled entries.
- `src/extension.ts:1300-1309` passes the same settings manager and canonical agent directory to `createAgentSession`, while preserving the explicit CodePi `sessionManager` supplied by the runtime. The runtime itself is also created with `state.sessionManager` at `src/extension.ts:1313-1316`.
- Focused validation run: `npx vitest run src/__tests__/pi-runtime-config.test.ts` passed (3 tests). The submitted report also records TypeScript and the broader focused resource/storage tests as passing; no broad suite was run for this review.

### Blocker
- **Blocker — implicit theme override is lost before runtime initialization (`src/extension.ts:1270-1300`).** The code calls `settingsManager.applyOverrides({ theme: "nebula-pulse" })` at line 1274, then calls `await loader.reload()` at line 1300. In the actual SDK, `DefaultResourceLoader.reload()` begins with `await this.settingsManager.reload()` (`node_modules/@earendil-works/pi-coding-agent/dist/core/resource-loader.js:228-230`). `SettingsManager.reload()` reconstructs `settings` from disk and therefore removes the in-memory override (`node_modules/@earendil-works/pi-coding-agent/dist/core/settings-manager.js:206-224` and `:300-303`). Consequently, with no explicit user theme, the shared manager passed to `createAgentSession` and `InteractiveMode` no longer contains `nebula-pulse`; the interactive theme controller sees `undefined` (`node_modules/@earendil-works/pi-coding-agent/dist/modes/interactive/theme/theme-controller.js:15-16`) rather than the required implicit bundled theme. This is not a persistence issue—the override is non-persistent—but it does not survive the required SDK initialization. Apply the override after `loader.reload()` (or otherwise reapply it after every reload) while retaining the explicit-theme guard.

### Issues by severity
- **Blocker:** `src/extension.ts:1270-1300` — in-memory `nebula-pulse` override is applied before SDK reload and is erased by `SettingsManager.reload()`; implicit theme requirement is unmet at runtime.
- **Note:** `src/__tests__/pi-runtime-config.test.ts:52-67` only tests a pure options object. It does not exercise `DefaultResourceLoader.reload()`, shared `SettingsManager` identity, effective theme initialization, or actual extension ordering/first-registration precedence. Add a focused mocked-loader or SDK-semantic test when fixing the blocker so this regression cannot recur.
- **Note:** `src/pi-runtime-config.ts:74-80` exports `defaultRuntimeResourceConfig()` but the function is unused and duplicates defaults already defined in `src/pi-store.ts:76-79`. Removing it or using the canonical policy would reduce dead code; this is not a spec blocker.
- **Expected residual:** The legacy first-run import prompt remains in `src/extension.ts:258-319`, as documented in the task report. Per the brief, Task 7 owns that migration; its presence alone is not treated as a blocker here.
