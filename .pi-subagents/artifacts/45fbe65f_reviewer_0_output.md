### Remaining issues by severity

- **P2 / minor — path construction is not fully consistent with the stated `path.join` requirement.** `src/settings-view.ts:152-154` constructs the settings path as ```${agentDir}/settings.json``` rather than `join(agentDir, "settings.json")`. The dashboard metadata paths themselves correctly use `join` at `src/settings-dashboard.ts:59-65`, and native open paths use `join` through `ensurePiJsonFileInDir`; consequently this is not a current blocker on the normal canonical path, but the helper should use `node:path.join` for the explicit requirement and cross-platform path hygiene.

- **P2 / minor — stable resource ids are only compile-time validated.** `src/settings-view.ts:123-136` treats every runtime id other than `nebula-pulse` as an extension id, so a malformed/untrusted webview message could add an arbitrary key under `codepi.bundledExtensions`. The protocol union documents the intended stable ids, but the backend should reject unknown ids before persistence. This does not escape the `codepi` namespace or affect normal typed callers, but it weakens the “stable resource id”/safe-toggle boundary.

- **Expected Task 6 residual — the old webview consumer is still present.** `webview-ui/src/settings/App.tsx` and legacy components still consume removed save/auth/import protocol members, so the webview build remains expected to fail until Task 6 rewrites that consumer. This is explicitly accepted by the Task 5 brief/report and is not counted as a Task 5 backend blocker.
